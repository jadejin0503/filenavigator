# SAS EG 快速打开（复用 EG + 对话框树导航）设计

日期：2026-04-30  
范围：PFN（`app_qt.py`）中 “用 SAS EG 打开 .sas” 的自动化流程

## 背景与问题

当前 PFN 在打开 `.sas` 时使用 `pywinauto` 做 UI 自动化以定位到服务器端 DDT 路径并打开文件。现状问题：

- **手动展开很快**：用户在 SAS EG 中按 `服务器 → SASApp → 文件 → projects/users → ...` 手动展开定位非常顺畅。
- **自动化很慢/不稳定**：同样的展开路径在自动化中耗时明显更长，且常出现展开不到位、需要额外点击才加载的情况。用户侧观测到的典型卡点为：**打开 EG 后展开 SASApp 很久**，随后 **展开“文件/Files”又要很久**。

从现有实现观察到的高风险点（需要改造）：

- 强制 **每次新启动** SAS EG 窗口（不复用已有实例）。
- 同时存在主界面树与对话框树两套逻辑，且夹杂 **屏幕固定坐标点击 SASApp**（对分辨率/布局/焦点非常敏感）。
- 展开/等待策略偏“固定 sleep + 枚举 children/descendants”，在 UIA 下容易慢。

## 目标（成功标准）

- **速度**：在 SAS EG 已运行的常见场景下，PFN 打开一个 `.sas` 文件应做到“接近手动展开速度”，避免因自动化策略引入额外的长等待。
- **稳定性**：避免固定坐标点击；减少对全窗口 `descendants()` 的依赖；在控件结构变动时仍能通过兜底策略给出可操作的提示。
- **多文件**：支持同一目录下多个 `.sas` 文件一次性打开；不同目录的多文件明确给出行为（见下）。
- **可控的超时与重试**：对用户反馈最慢的两个节点（`SASApp`、`文件/Files`）提供**明确的等待上限与重试策略**，避免出现“无限等/越等越慢”的体验。

非目标：

- 本次不改动 “数据集文件（`.sas7bdat` 等）直接传参打开” 的逻辑。
- 本次不追求跨目录的真正“一次性打开”（SAS EG 对话框能力有限），先保证同目录批量。

## 方案概述（选定）

选定 **方案 A**：

1. **优先复用已打开的 SAS EG 实例**（connect），若未运行再启动。
2. **以‘打开’对话框中的“浏览(服务器)”树为主**完成路径导航：
   - `Ctrl+O` 打开对话框
   - 切到 “服务器/Servers” 标签（若需要）
   - 点击 “浏览...” 进入你截图所示的“浏览(服务器)”对话框
   - 在左侧树按 `服务器 → SASApp → 文件 → projects/users → ...` 逐级展开到目标目录
   - 在右侧列表选中文件（单文件）或多选（同目录多文件），点击“打开”
3. **彻底移除/不再依赖**“屏幕固定坐标点击 SASApp”的路径。

## 用户交互与行为定义

### 1) 单文件（推荐路径）

- 输入：一个 `.sas` 文件的本机路径（通常为 `Z:\...`）。
- 行为：
  - 自动化定位到对应服务器侧目录（经 PFN 的 Z→DDT 映射规则换算得到路径段）
  - 在右侧文件列表中选中该文件并打开
- 失败时：
  - 若定位到目录但列表找不到文件：提示“目录已到达，但文件未出现在列表”，建议检查是否同名/大小写/文件同步。
  - 若树节点名称不匹配（例如 “文件” 节点在不同 EG 版本叫法不同）：提示并要求用 inspect 确认 ControlType/标题。

### 2) 同目录多文件（首要支持）

- 输入：多个 `.sas`，且必须位于同一父目录（现有 `_common_folder_and_files` 规则保持）。
- 行为：
  - 目录导航只做一次
  - 右侧列表中按顺序批量选中（Ctrl+点击）或逐个打开（取决于控件能力）
  - 一次点击“打开”

### 3) 不同目录多文件（明确降级）

- 默认行为：给出提示“多选文件需位于同一目录”，并引导用户分批次打开。
- 后续可选增强（不在本次范围）：按目录分组自动分批打开（每组一次导航 + 批量选择）。

## 技术设计细节

### 1) 复用 SAS EG 实例

优先：

- `Application(backend="uia").connect(title_re=".*SAS Enterprise Guide.*")`

找不到时：

- `start(seguide_path)` 启动新实例

注意：

- connect 时可能命中多个窗口，需按可见/前台窗口优先；必要时允许用户在配置里选择“总是新开”或“尽量复用”（默认复用）。

### 2) 打开对话框链路（主路径）

核心步骤（每步都要求“状态驱动等待”，避免固定长 sleep）：

- 将 EG 主窗口 `set_focus()`
- 发送 `Ctrl+O`
- 等待“打开”对话框 ready（按标题/ControlType 定位）
- 若存在标签页：
  - 切到“服务器/Servers”标签（复用现有 `_saseg_click_server_tab` 但将查找范围缩小到 TabItem）
- 点击 “浏览...” 打开“浏览(服务器)”对话框
- 在“浏览(服务器)”对话框中：
  - 左侧树：逐级展开 `服务器` → `SASApp` → `文件` → `projects/users` → `...`
  - 右侧列表：按文件名定位 ListItem/DataItem 并选中
  - 点击“打开”

### 3) 树展开策略（关键优化点）

每一级展开采用统一策略：

- **只在当前节点范围内找下一层**（`child_window` + `control_type="TreeItem"`），不要用全窗口 `descendants()`。
- 展开后 **等待目标子节点出现**（例如展开 `文件` 后等待出现 `projects`/`users`），作为“展开完成”的判据（不要用 `children()` 的“数量>0”当作展开成功，因为 UIA 下可能触发虚拟化/延迟加载，导致误判与额外等待）。
- 失败重试：
  - 同一层最多重试 2 次（点击节点、展开、短等待）
  - 仍失败则抛出“定位失败”的分段错误（指出失败的层级名称）

#### 针对 `SASApp` 与 `文件/Files` 的明确超时策略（默认值）

由于用户反馈自动化最慢的步骤集中在 **展开 `SASApp`** 与 **展开 `文件/Files`**，本方案要求在实现中把这两步做成“可调参数 + 明确判据”。

默认建议（后续可通过集中常量调整）：

- `SASApp`：
  - **判据**：展开后在 `SASApp` 子节点下能找到 `文件/Files`（或其候选名称之一）。
  - **等待上限**：单次尝试 4s。
  - **重试次数**：2 次（总预算约 8–10s，含短间隔与一次聚焦点击）。
- `文件/Files`：
  - **判据**：展开后在 `文件/Files` 子节点下能找到 `projects` 或 `users`（按 path_type 至少其一出现）。
  - **等待上限**：单次尝试 4s。
  - **重试次数**：2 次。
- 其他中间节点（例如 `服务器`、`projects/users` 及后续目录层级）：
  - **判据**：目标子节点出现（下一层 TreeItem 按 title 匹配到）。
  - **等待上限**：单次尝试 2s。
  - **重试次数**：2 次。

若在上述预算内仍失败：

- 立即结束本次自动化并给出“失败层级 + 建议手动确认控件名称/使用 inspect”的提示；
- 不要继续做大范围枚举或无限循环等待。

### 4) 右侧列表选中策略

沿用现有 `_select_file_in_list` / `_batch_select_and_open_in_dialog` 的思路，但在对话框上下文内做两点约束：

- 优先从“右侧列表控件”内枚举子项（List/ListView/DataGrid），其次才全对话框兜底。
- 在导航到目标目录后，先触发一次“目录点击”确保列表刷新，再开始匹配文件名。

### 5) 路径映射与目录层级

- PFN 仍以本机 `Z:\...` 为输入来源。
- 目录层级的 `folder_parts` 仍可按现有逻辑从 `Z:\` 去掉盘符后拆分得到（例如 `projects\...`、`users\...`）。
- 树导航使用的是 `projects/users/...` 的层级段，不依赖直接输入 `/u01/.../DDT/...`（因为该输入在你当前 EG 对话框中不可用）。

## 错误处理与可观测性

### 1) 状态栏打点（用户可感知）

至少包含：

- 已连接/启动 EG
- 已打开“打开”对话框
- 已打开“浏览(服务器)”对话框
- 正在展开：服务器 / SASApp / 文件 / projects/users / <后续层级>
- 已选中文件 / 正在打开

建议补充（用于定位“慢在何处”）：

- 在关键节点完成时输出耗时：例如 “SASApp 就绪（x.xs）”、“Files 就绪（x.xs）”。

### 2) 失败提示（精确到步骤）

示例：

- “无法在‘浏览(服务器)’对话框中找到节点：SASApp”
- “已到达目录，但右侧列表未找到文件：xxx.sas”
- “多选文件不在同一目录，已取消批量打开”

## 测试计划

- 单文件：从 PFN 选择一个 `.sas`，验证自动定位并打开（多次重复）。
- 同目录多文件：选中 3 个 `.sas`，验证一次定位后批量打开。
- 失败路径：手动改一个不存在的文件名（或断开 Z 盘），验证错误提示清晰。

## 兼容性与风险

- 不同 EG 版本/语言可能导致控件标题差异（“文件/Files”等）：需集中维护候选名称列表，并尽量基于 ControlType + 层级定位。
- “浏览(服务器)”对话框右侧列表的 ControlType 可能在不同环境中不同：保留 inspect 指引作为最后兜底。
